# Техническое задание (v0.2)

Черновик. Заменяет раздел "Техническое задание" из первой версии README: проект превратился из личного дневника в каталог чая с дневником дегустаций и оценками (по аналогии с RateYourMusic).

## 1. Назначение

cha-log - закрытый каталог китайского чая со свойствами (категория, регион, производитель, вид и др.), в котором зарегистрированные пользователи ведут дневник дегустаций, ставят оценки и пишут комментарии. На странице каждого чая видна средняя оценка и дегустации других пользователей.

## 2. Роли

| Роль | Возможности |
|------|-------------|
| Гость | Просмотр каталога и страниц чаёв (уточнить, см. открытые вопросы), регистрация, вход |
| Пользователь | Всё, что у гостя, плюс дневник дегустаций, оценки, предложения новых чаёв |
| Администратор | Всё, что у пользователя, плюс управление каталогом и справочниками, рассмотрение предложений |

## 3. Функциональные требования (MVP)

### Каталог

| № | Требование |
|---|------------|
| FR-1 | Просмотр каталога чаёв с фильтрами (категория, регион, производитель, год сбора), сортировкой (название, средняя оценка, число дегустаций, год) и поиском по названию. |
| FR-2 | Страница чая: свойства, средняя оценка и число оценок, список дегустаций пользователей с комментариями. |
| FR-3 | Администратор создаёт, редактирует и удаляет чаи и справочники (категории, регионы, производители, способы заваривания). Удалять записи, на которые есть ссылки, нельзя. |

### Аккаунты

| № | Требование |
|---|------------|
| FR-4 | Регистрация, вход и выход. Пароли хранятся только в виде хеша. |
| FR-5 | Роли «пользователь» и «администратор»; права проверяются на сервере. |

### Дегустации

| № | Требование |
|---|------------|
| FR-6 | Пользователь добавляет дегустацию: чай из каталога, дата и время (можно в прошлом), способ заваривания, температура воды, оценка и комментарий. Необязательно: вес листа, объём воды, заметка про время и проливы. |
| FR-7 | Оценка от 0,5 до 5 звёзд с шагом 0,5. В БД хранится целым числом от 1 до 10. Оценка у каждой дегустации своя, потому что один чай по-разному раскрывается при разных способах заваривания. |
| FR-8 | Пользователь редактирует и удаляет только свои дегустации. |
| FR-9 | Страница «Мой дневник»: свои дегустации с фильтрами (чай, категория, период, способ заваривания, оценка) и сортировкой. |

### Предложения новых чаёв

| № | Требование |
|---|------------|
| FR-10 | Пользователь отправляет предложение нового чая. Производитель и регион можно ввести свободным текстом, если их нет в справочниках. |
| FR-11 | Администратор просматривает предложения и одобряет (в каталоге создаётся чай) или отклоняет с комментарием. Пользователь видит статус своих предложений. |

### Файлы и отчёты

| № | Требование |
|---|------------|
| FR-12 | Экспорт данных в файл (CSV или Excel): дневник пользователя, а для администратора ещё и каталог. |
| FR-13 | Импорт чаёв из файла CSV (администратор) с проверкой данных и отчётом об ошибках по строкам. |
| FR-14 | Отчёт в офисном формате (Excel или Word), например дегустации за период со сводной статистикой. Формат уточним позже. |

## 4. После MVP

- Теги (вкус, аромат) и коллекции чаёв.
- Ссылки на магазины, где можно купиь конкретный чай.
- Статистика и графики.
- Предложения правок для существующих чаёв.
- Фото чая и настоя.
- Таймер проливов и таблица проливов.
- Публичные профили, лайки и комментарии к дегустациям.
- PWA.

## 5. Нефункциональные требования

| № | Требование |
|---|------------|
| NFR-1 | Интерфейс на русском языке (после MVP возможно добавление английского и других). |
| NFR-2 | Приоритет десктопу, адаптивная вёрстка для телефона (ширина от 360 px). |
| NFR-3 | Безопасность: хеширование паролей, проверка прав на сервере, валидация входных данных, секреты не хранятся в репозитории. |
| NFR-4 | Публичный репозиторий, работа через ветки и Pull Request, коммиты по Conventional Commits. |
| NFR-5 | На каждый Pull Request автоматически запускаются линтер и тесты (GitHub Actions). |
| NFR-6 | Развёртывание настраивается после MVP (обязательно для курсовой). |

## 6. Критерии готовности MVP

- Выполнены FR-1 – FR-14 и NFR-1 – NFR-5.
- Приложение запускается локально по инструкции из README.
- Есть автотесты для API и ключевых сценариев интерфейса.
- CI на `main` зелёный.
- Каталог содержит достаточно записей для демонстрации (около 125 чаёв из открытого датасета с русскими переводами).

## 7. Вне рамок

Модерация комментариев, социальная сеть, мобильное приложение, рекомендательная система.

## 8. Вопросы на подумать

- Видит ли гость каталог и оценки или только страницу входа?
- Нужно ли подтверждение имейла и восстановление пароля?
- Теги крепятся к чаю (общие) или к дегустации (личные заметки о вкусе)?
- Нужно ли поле "форма чая" (рассыпной, блин, кирпич)?
- Какой формат отчёта: Excel или Word?

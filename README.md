# ЧА-ЛОГ
Онлайн-платформа и база данных для каталогизации, оценки и обсуждения китайского (и не только) чая.

# 🍵 Чайный дневник

[![CI](https://github.com/dnslm/cha-log/actions/workflows/ci.yml/badge.svg)](https://github.com/dnslm/cha-log/actions/workflows/ci.yml)

Веб-приложение для любителей китайского чая: каталог чаёв со свойствами и личный дневник дегустаций с оценками и комментариями, по аналогии с RateYourMusic.

> Статус: каркас и CI есть, остальное на этапе идей. Проект взят в качестве инициативной темы на курсовую работу 2 курса разработки информационных систем для бизнеса.

## Цели проекта

- **Учебная.** На реальном проекте освоить и закрепить: Git и GitHub-процесс (ветки, Pull Request, Issues), React, Node.js, REST API, SQL и ORM, аутентификацию, автотесты и CI/CD.
- **Практическая.** Заменить бумажные заметки удобным дневником с поиском и фильтрами, а заодно собрать каталог чая с оценками.
- **Курсовая.** Проект выполняется как курсовая работа по веб-разработке (информационная система с реляционной БД).

## Техническое задание

Полное ТЗ: [docs/tz.md](docs/tz.md). Модель данных: [docs/data-model.md](docs/data-model.md).

### Кратко

- **Роли.** Гость (просмотр), пользователь (дневник, оценки, предложения чаёв), администратор (каталог и модерация).
- **Каталог.** Закрытый каталог чаёв: название, категория, регион, производитель, вид или сорт, год. Список с фильтрами, сортировкой и поиском, страница чая со средней оценкой и дегустациями пользователей. Каталог ведёт администратор.
- **Аккаунты.** Регистрация, вход, роли. Пароли хранятся только в виде хеша.
- **Дневник.** Дегустация: чай из каталога, способ заваривания, температура воды, оценка от 0,5 до 5 звёзд с шагом 0,5, комментарий. Оценка у каждой дегустации своя, потому что один чай по-разному раскрывается при разных способах заваривания. Страница "Мой дневник" с фильтрами и сортировкой.
- **Предложения.** Пользователь предлагает новый чай, администратор одобряет или отклоняет.
- **Файлы.** Импорт чаёв из CSV, экспорт данных, отчёт в офисном формате.
- **Общее.** Интерфейс на русском. Основное устройство ноутбук, на телефоне тоже должно быть удобно. Данные в реляционной БД, клиент работает с сервером через REST API.

### После MVP (по желанию)

- Теги вкуса и аромата, коллекции чаёв.
- Статистика и графики.
- Фото чая и настоя, таймер проливов.
- Публичные профили, лайки и комментарии к дегустациям.
- PWA (установка на телефон, офлайн-режим).

### Критерии готовности MVP

- Выполнены все функциональные и нефункциональные требования из [ТЗ](docs/tz.md).
- Приложение запускается локально по инструкции из этого README.
- Есть автотесты для API и нескольких ключевых сценариев интерфейса.
- CI на `main` зелёный.

### Вне рамок

Модерация комментариев, соцсеть, мобильное приложение, рекомендательная система, онлайн-оплата.

## Технологии (план)

| Слой | Выбор | Примечание |
|------|-------|------------|
| Фронтенд | React + Vite, JavaScript | TypeScript можно подключить позже отдельной задачей |
| Бэкенд | Node.js + Express, REST API | |
| База данных | SQLite на разработке | Переход на PostgreSQL обсудим при деплое |
| ORM | Prisma или Drizzle | Выбор и обоснование на этапе 1 |
| Аутентификация | Хеш паролей, сессии или токены | Выбор на этапе 3 |
| Тесты | Vitest | Для фронтенда и бэкенда |
| CI | GitHub Actions | См. `.github/workflows/ci.yml` |

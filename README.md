# 🍵 Чайный дневник

[![CI](https://github.com/dnslm/tea-diary/actions/workflows/ci.yml/badge.svg)](https://github.com/dnslm/tea-diary/actions/workflows/ci.yml)

Веб-приложение для записи чайных сессий: какой чай, как заваривал, что почувствовал. Заметки хранятся в базе данных, их можно искать, фильтровать и сравнивать.

> Статус: ничо нету, но есть идея и вайб сделать.

## Цели проекта

- **Учебная.** На реальном небольшом проекте освоить и закрепить: Git и GitHub-процесс (ветки, Pull Request, Issues), React, Node.js, REST API, SQL и ORM, автотесты и CI/CD.
- **Практическая.** Заменить бумажные заметки удобным дневником с поиском и статистикой.

## Техническое задание

### Пользователь и контекст

- Пользователь один (йа). Аккаунтов в MVP нет, но модель данных проектируется так, чтобы их можно было добавить без переделки.
- Основное устройство — ноутбук. Интерфейс должен нормально работать и на телефоне.
- Язык интерфейса — русский.
- Накопленные заметки существуют только на бумаге, автоматического импорта не будет: записи переносятся вручную.

### Функциональные требования (MVP)

| № | Требование |
|---|------------|
| FR-1 | **Чаи.** Создание, просмотр, редактирование и удаление. Поля: название, категория (улун, белый, пуэр, зелёный, красный, другое), сорт или вид, регион или производитель, год сбора, продавец, цена, вес, статус (в наличии или закончился), заметка. |
| FR-2 | **Сессии.** Создание, просмотр, редактирование и удаление. Поля: чай, дата и время, посуда, вес листа (г), объём воды (мл), температура воды (°C), аромат, вкус, послевкусие, состояние, общая заметка, оценка. |
| FR-3 | **Проливы.** Внутри сессии список проливов: номер, время настоя (сек), заметка. Проливы можно добавлять, менять и удалять. |
| FR-4 | **Оценка.** От 0,5 до 5 звёзд с шагом 0,5 (как в RYM). В БД хранится целым числом от 1 до 10. Оценка необязательна. |
| FR-5 | **Список сессий** с фильтрами (по чаю, категории, периоду дат, оценке) и текстовым поиском по заметкам. |
| FR-6 | **Страница чая**: все данные чая, история его сессий, количество сессий и средняя оценка. |
| FR-7 | **Дата сессии** вводится вручную и может быть в прошлом, чтобы переносить бумажные заметки. |
| FR-8 | Данные хранятся в БД, клиент общается с сервером через REST API. |

### После MVP (по желанию)

- Таймер проливов прямо в форме сессии.
- Теги вкуса и аромата.
- Фото чая и настоя.
- Экспорт и импорт данных (JSON, CSV).
- Статистика: что пью чаще всего, динамика оценок.
- PWA (установка на телефон, офлайн-режим).
- Аккаунты и авторизация.

### Нефункциональные требования

| № | Требование |
|---|------------|
| NFR-1 | Интерфейс на русском языке. |
| NFR-2 | Адаптивная вёрстка: удобно на ноутбуке, читаемо и пригодно для ввода на телефоне (ширина от 360 px). |
| NFR-3 | Схема БД допускает добавление аккаунтов без переделки существующих таблиц (см. [docs/data-model.md](docs/data-model.md)). |
| NFR-4 | Публичный репозиторий. Работа идёт через ветки и Pull Request, коммиты оформляются по Conventional Commits (см. [docs/workflow.md](docs/workflow.md)). |
| NFR-5 | На каждый Pull Request автоматически запускаются линтер и тесты (GitHub Actions). |
| NFR-6 | Секреты и локальные базы данных не попадают в репозиторий. |
| NFR-7 | Деплой (CD) настраивается после MVP. |

### Критерии готовности MVP

- Выполнены FR-1 – FR-8 и NFR-1 – NFR-6.
- Приложение запускается локально по инструкции из этого README.
- Есть автотесты для API и нескольких ключевых сценариев интерфейса.
- CI на `main` зелёный.

### Вне рамок

Многопользовательский режим, социальные функции, мобильное приложение, рекомендации.

## Технологии (план)

| Слой | Выбор | Примечание |
|------|-------|------------|
| Фронтенд | React + Vite, JavaScript | TypeScript можно подключить позже отдельной задачей |
| Бэкенд | Node.js + Express, REST API | |
| База данных | SQLite на разработке | Переход на PostgreSQL обсудим при деплое |
| ORM | Prisma или Drizzle | Выбор и обоснование на этапе 1 |
| Тесты | Vitest | Для фронтенда и бэкенда |
| CI | GitHub Actions | См. `.github/workflows/ci.yml` |
